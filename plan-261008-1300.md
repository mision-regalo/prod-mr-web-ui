**Date:** 2026-10-11  
**Project:** Gift Mission / Misión Regalo (formerly Missions Presents)  
**Specification Version:** 2.0 (Comparison between Updated Specification vs. Initial Specification)

## 1. Executive Summary of Differences

A comprehensive comparison between the initial specification (Base Document) and the updated specification (New Document) reveals that the new version transitions the application from a static capture and reassignment tool into a **multi-role, fully configurable, mobile-first enterprise web platform**. Key structural enhancements include:

1. **Gift-Giving Day Events Management:** A dedicated entity with a single-character ID (`A`, `B`, `C`, `X`, `G`), location, dates, and letter fulfillment goal.
2. **Letter Folio Re-architecture:** Replaced the composite community ID with a **Folio Type** (Gift-Giving Day ID) plus a **Manual Numeric Folio** entered during physical letter review, along with **physical letter photo attachment**.
3. **Dynamic Coordinator-to-Leader Hierarchy:** When a Coordinator is selected, the Leader is **automatically pre-filled and set to read-only**. If no Coordinator is selected, all available Leaders are listed.
4. **Closing Letters Capture Module:** Protected by the **`NC`** permission, enabling Leaders and Admins to lock or unlock CRUD operations in bulk for letters under their umbrella.
5. **Elementary Schools Catalog:** Protected by the new **`CS`** privilege for standalone management.
6. **Dynamic Users & Role-Based Permissions (RBAC) Engine:** Full CRUD for Users and Roles, dynamic permission toggles, bulk assignment, and deletion guards (preventing deletion of roles with assigned users).
7. **Expanded Permission Matrix:** Introduction of **`CE`**, **`CS`**, and **`NC`** permissions.
8. **Strict Mobile-First UI/UX Requirements:**
   * Rendering priority: **1st Mobile cellphones**, **2nd Tablets**, **3rd Desktop computers**.
   * Left navigation drawer on desktop with a hamburger toggle; **Bottom Navigation Bar on mobile devices**.
   * Text avatar in the top-right corner displaying the user's name on **hover**, accompanied by a **Log-out** option.
   * System-wide **Dark Mode** support and bilingual localization (English: *Gift Mission*, Spanish: *Misión regalo*).

## 3. Official RBAC Permission Matrix

| Code | Allowed Action | Admin | Leader | Coordinator |
| :---: | :--- | :---: | :---: | :---: |
| **CL** | CRUD Leaders | **Y** | N | N |
| **CC** | CRUD Coordinators | **Y** | **Y** | N |
| **CD** | CRUD Donors | **Y** | **Y** | **Y** |
| **CL** | CRUD Letters (*CLett*) | **Y** | **Y** | **Y** |
| **CE** | CRUD Gift-Giving Day Events | **Y** | N | N |
| **CS** | Manage Elementary Schools Catalog | **Y** | N | N |
| **NC** | Closing Letters Capture (*Bulk Lock/Unlock*) | **Y** | **Y** | N |
| **RP** | Reassign Presents (Simulation & Manual) | **Y** | **Y** | N |
| **SWR**| Send WhatsApp Reminders | **Y** | N | N |
| **SER**| Send Email Reminders | **Y** | N | N |
| **SCC**| View Coordinator Column & Filter in Reports | **Y** | **Y** | N |

### Business Integrity Rules:
1. **Leader Deletion Guard:** A Leader cannot be deleted if Coordinators are assigned to them.
2. **Coordinator Deletion Guard:** A Coordinator cannot be deleted if letters are assigned to them.
3. **Donor Deletion Guard:** A Donor cannot be deleted if letters are assigned to them.
4. **Role Deletion Guard:** A Role cannot be deleted if users are currently assigned to that role.
5. **Non-Destructive Letter Archiving:** Only Leaders and Admins can delete letters, which are moved to a recoverable archive vault instead of being permanently deleted.
6. **Reassignment Authority:** Only Leaders and Admins have permission to execute gift reassignments (`RP`).

## 4. Phased Implementation Roadmap

### Phase 1: Data Model & TypeScript Types Refactoring (`src/types/index.ts`)
1. **Gift-Giving Day Events (`GiftGivingEvent`):**
   * `id`: Single character (`'A' | 'B' | 'C' | 'X' | 'G' | string`).
   * `location`: String (e.g., Zapopan, Guadalajara, Refugio).
   * `dates`: String (e.g., "Nov 28th, Nov 29th").
   * `goal`: Number (letter target goal).
2. **Letter Schema Enhancements (`Letter`):**
   * `folioType`: Event ID character (`A`, `B`, etc.).
   * `folio`: Number (manually captured from physical letter).
   * `id`: Composite identifier format (e.g., `A-1042`).
   * `photoUrl`: Optional string for the physical letter image.
   * `isLocked`: Boolean indicating if capture/editing is locked under `NC`.
3. **Dynamic Users & Custom Roles (`User`, `CustomRole`):**
   * `User`: `id`, `name`, `email`, `roleIds`, `assignedLeaderId`, `assignedCoordinatorId`, `active`.
   * `CustomRole`: `id`, `name`, `description`, `permissions` (record of the 11 permissions), `userCount`.
4. **Permission Types Extension:**
   * Extend `PermissionKey` to include `'CE' | 'CS' | 'NC'`.

### Phase 3: Gift-Giving Day Events Module (`EventsView.tsx`)
1. **Access Control:** Restricted strictly to users with the `CE` permission.
2. **Event Dashboard:** KPI cards displaying progress toward letter fulfillment goals (`Letters Captured / Goal`).
3. **CRUD Operations:** Modal dialog to create and edit events (ID, Location, Dates, Goal).

---

### Phase 4: Letters Registration & Form Upgrades (`LettersView.tsx`)
1. **Folio Selection & Capture:**
   * Dropdown to select the Event / Folio Type (`A`, `B`, `C`, `X`, `G`).
   * Manual numeric input for the `folio` number.
2. **Dynamic Coordinator-to-Leader Dependency:**
   * When a Coordinator is chosen from the dropdown:
     * Auto-select the Coordinator's assigned Leader.
     * Disable the Leader field (`read-only`).
   * When no Coordinator is chosen:
     * Enable the Leader dropdown with all available Leaders.
3. **Physical Letter Photo Attachment:**
   * File upload input supporting image formats with instant thumbnail preview and zoom dialog.
4. **Edit Lock Enforcement:**
   * Visually flag letters with `isLocked === true` (locked via `NC`), disabling edit/delete controls for non-authorized users.

---

### Phase 5: Closing Letters Capture Module (`ClosingLettersView.tsx`)
1. **Access Control:** Visible only to users with the `NC` permission (Admins & Leaders).
2. **Umbrella Scoping:**
   * Leaders view only letters assigned to their team.
   * Admins can filter across all Leaders or inspect the entire registry.
3. **Bulk Lock/Unlock Operations:**
   * Checkbox multi-selection per row.
   * Actions: **"Lock Selected Letters"** and **"Unlock Selected Letters"**.
   * Status indicators displaying locked vs. open capture state.

---

### Phase 6: Elementary Schools Catalog Module (`SchoolsView.tsx`)
1. **Access Control:** Visible only to users with the `CS` permission.
2. **CRUD Management:** Add, edit, and deactivate school names.
3. **Safety Check:** Prevent school deletion if letters are linked to that school.

---

### Phase 7: Dynamic User & Role Administration Modules
1. **Roles & Permissions Management (`RolesManagementView.tsx`):**
   * Table of roles with user counts and active permissions.
   * Interactive 11-permission toggle matrix.
   * Validation rule: **Prevent role deletion if active users are assigned**.
   * Bulk user assignment modal.
2. **Users Management (`UsersManagementView.tsx`):**
   * User list with name, email, assigned role, and status.
   * Dialog to create users and assign roles.

3. **Dark Mode Integration:**
